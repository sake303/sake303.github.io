SG

Oura vs WHOOP, inside an AI-assisted sleep and recovery workflow.

I am using both and keeping track of what changes the workflow: data export and API access, freshness, HealthMes integration friction, price, comfort, and battery.

I mostly care about what happens after the wearable leaves my wrist. Can an agent get the data, trust that it is current, and use it in the right place when the workflow runs?

Current note

The actual-sleep Calendar preview is back in HealthMes. The work started with a stale provider: Hermes prepared two Calendar blocks, but there was no fallback write and the Calendar stayed unchanged.

That made the comparison more concrete. It is not enough for an agent to receive approval. The provider needs to be live, and the result needs to show up where the workflow expects it.

What I am comparing

  • Data export and API access
  • Freshness: when the data is actually available to use
  • HealthMes integration friction
  • Price, comfort, and battery for living with the device

App UX only matters here when setup, consent, export, or recovery changes the agent workflow.
