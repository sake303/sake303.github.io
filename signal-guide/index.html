Which is better for an agent workflow: Oura or WHOOP?

I use both Oura and WHOOP in my sleep and recovery agent setup. I connect them to an agent, use them myself, and keep track of which one is less of a hassle.

There are four things I'm still testing:

  1. Whether I can pull the data through an API or export
  2. What the data latency is
  3. How complex the auth flow is when I wire it into an agent
  4. Whether I can keep the data pipeline running given the cost, comfort, and battery burden

Current note

On August 20, I put the same question to Codex. HealthMes checked my WHOOP Recovery and that day's Cycle strain, then Hermes sent the answer to Telegram. When the data looked stale or unclear, it stopped instead of guessing.

That one run doesn't settle Oura versus WHOOP. It did show me where Hermes had failed before: the provider can be healthy and the agent can still miss the data if the runtime drops it.

The decision table

  • Getting the data out, and whether there is an API
  • How fresh the data is when the workflow runs
  • What it takes to connect the data to an agent
  • Price, comfort, and battery

I care about the app when it changes what the agent can do: setup, consent, export, or recovery. Everything else is secondary here.

현재 기록

8월 20일에 같은 질문을 Codex에 던졌습니다. HealthMes가 제 WHOOP Recovery와 그날의 Cycle strain을 확인했고, Hermes가 답을 Telegram으로 보냈습니다. 데이터가 오래됐거나 불분명할 때는 추측하지 않고 멈췄습니다.

한 번의 dogfood run으로 Oura와 WHOOP 중 무엇이 낫다고 말할 수는 없습니다. 다만 Hermes가 이전에 실패한 지점은 보였습니다. 데이터 제공자가 정상이어도 실행 환경이 끊기면 agent는 데이터를 놓칠 수 있습니다.

최근 provider capability 리뷰에서 한 가지 경계를 더 확인했습니다. 데이터 소스가 연결되어 있어도, 지금 필요한 의사결정에 쓸 신호를 제공한다는 뜻은 아닙니다. 그래서 Oura와 WHOOP을 앱 기능 수가 아니라 데이터 접근, 신선도, 인증 과정, 그리고 일상적으로 워크플로우를 유지할 수 있는지로 비교합니다.

결정표

  • 데이터를 꺼낼 수 있는지, API가 있는지
  • 워크플로우가 실행될 때 데이터가 얼마나 최신인지
  • 에이전트에 연결하는 데 무엇이 필요한지
  • 가격, 착용감, 배터리

이 앱이 에이전트가 할 수 있는 일을 바꿀 때만 중요하게 봅니다. 세팅, 동의, 내보내기, 회복 판단이 여기에 해당합니다. 그 밖의 것은 여기에서는 부차적입니다.

WHOOP 흐름은 HealthMes PR #157에 있고, 아직 리뷰 중입니다. dogfood run과 Signal Guide 후속 기록은 X에 남겨 두었습니다.

코드 리뷰에서 작은 엣지 케이스를 찾았습니다. manual과 Manual이 같은 source의 레코드를 두 개 만들 수 있었습니다.

수정 자체는 작았습니다. 이 작업을 하며 제가 지금 무엇을 만드는지 다시 봤습니다. 지금은 WHOOP 데이터를 좁게 가져오는 흐름을 만들고 있습니다. 더 넓은 웰니스 플랫폼은 다른 프로젝트고, 아직 그것을 할 근거가 없습니다.

이 기록은 제품을 만들고 직접 써 본 뒤 공개하는 과정에서 남겼습니다. 그날은 작동했습니다. 두 번째 코드 리뷰인 PR #199에는 식별, 수정 이력, 시간 경계, 출처에 대한 리뷰 코멘트가 남아 있습니다. 그래서 이 기록을 어떤 기기가 이겼다는 증거로 보지 않고, 빌드 노트로 남겨 둡니다.
