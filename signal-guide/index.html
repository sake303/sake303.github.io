SG

I'm using Oura and WHOOP in my own agent-assisted sleep and recovery workflow. SG is the guide I'm making from those notes.

I'm using both and noting what gets in the way: getting the data out, checking how fresh it is, connecting HealthMes, and then the boring real-life stuff: price, comfort, and battery.

The part I keep coming back to starts after the wearable leaves my wrist. Can the agent fetch the data, tell whether it is current, and put it where it needs to go?

Current note

On August 20, I ran that same question through an actual WHOOP path: Codex to HealthMes to Hermes to Telegram. It returned a recovery package using WHOOP Recovery and the Cycle's current day strain. When the input was stale or uncertain, it held off.

That is one direct-use result, not an Oura or WHOOP verdict. The earlier Hermes runtime gap still matters: a healthy data provider has to make it through the agent runtime before the agent can use it.

What I'm checking

  • Getting the data out, and whether there is an API
  • How fresh the data is when the workflow runs
  • What it takes to connect HealthMes
  • Price, comfort, and battery

I only look at the app when it changes the agent workflow: setup, consent, export, or recovery.

Build log

On August 17, I reproduced an HTTP MCP runtime gap after a Hermes self-update and added the evidence to the upstream issue. The public build note is on X.

The working WHOOP path is in HealthMes PR #157, which is open for review. The public receipts are on the first WHOOP dogfood note and the Signal Guide follow-up.

I am treating this as a dogfooding receipt in my Product to Build to Dogfooding to Public loop: evidence of one workflow, not a market or purchase recommendation.

Status: I'm still using both. I'll keep adding notes here as I go.
