Current note

On August 20, I put the same question to Codex. HealthMes checked my WHOOP Recovery and that day's Cycle strain, then Hermes sent the answer to Telegram. When the data looked stale or unclear, it stopped instead of guessing.

That one run doesn't settle Oura versus WHOOP. It did show me where Hermes had failed before: the provider can be healthy and the agent can still miss the data if the runtime drops it.

The decision table

  • Getting the data out, and whether there is an API
  • How fresh the data is when the workflow runs
  • What it takes to connect HealthMes
  • Price, comfort, and battery

I care about the app when it changes what the agent can do: setup, consent, export, or recovery. Everything else is secondary here.

WHOOP build log

The WHOOP flow is in HealthMes PR #157, still open for review. I wrote about the dogfood run and the Signal Guide follow-up on X.

A separate code review caught a source-id edge case: manual and Manual could create two records for the same source. The casing fix is simple. The useful question is whether this stays a narrow WHOOP retrieval flow, or grows into a general wellness platform.

This was one dogfood run in my Product to Build to Dogfooding to Public loop. It worked that day. The PR still has open review comments about identity, revisions, time boundaries, and provenance, so I'm treating this as a build note, not proof that one device wins.
